# finance_inbox — прямой канал данных в Финансиста

Сюда кладутся файлы с деньгами. Не в чат, не в бота — **файлом в эту папку**.
Всё, что здесь лежит, Финансист импортирует сам: при `/sync`, при старте бота и
при каждом моём (Claude Code) запуске `python3 finance_core.py`.

## Почему так, а не через бота

Бот хорош для вопросов, но плох как канал данных: пересланный документ живёт в
переписке, его нельзя перечитать через год и нельзя сверить. Файл в репозитории —
можно: у него есть история, дата, автор и контрольная сумма.

Главное: **импорт привязан к sha256 содержимого файла**, а не к «версии сида».
Раньше база не обновлялась именно потому, что импорт был закрыт константой версии:
файл менялся — система считала, что уже всё залила. Теперь наоборот — изменился
хоть один байт, файл перезаливается автоматически; не изменился — работа не
делается. Обмануть нечем.

## Как назвать файл (по имени определяется тип)

| Имя файла | Что внутри |
|---|---|
| `bank_*.csv` | банковская выписка, экспорт из онлайн-банка |
| `bank_*.json` | выписка в JSON (как `bank_seed.json`) |
| `invoices_*.json` | выставленные счета |

Примеры: `bank_2026-07.csv`, `bank_2026-08.csv`, `invoices_2026H2.json`.
Файлы не перезаписывают друг друга — можно докладывать по месяцам.

## Банковская выписка CSV — как получить

Naspa (и любой немецкий банк) → онлайн-банкинг → Umsätze → период → **Export/CSV**.
Формат менять не надо: импортёр сам определяет кодировку (UTF-8/CP1252/Latin-1),
разделитель (`;` или `,`) и находит колонки по немецким заголовкам —
`Buchungstag`/`Valutadatum`, `Betrag`, `Verwendungszweck`, `Beguenstigter`.
Немецкие суммы (`1.234,56`) понимает.

Если заголовки окажутся незнакомыми, импортёр **явно скажет об ошибке** и покажет,
какие колонки увидел, — а не молча запишет ноль строк. Пришли такой файл как есть,
я добавлю формат.

## Минимальный формат, если экспорта нет

`bank_ручной.csv` — четыре колонки, первая строка заголовок:

```csv
date,amount,party,category
2026-07-03,1500.00,"FSV Frankfurt RN 010726",client_income
2026-07-08,-240.50,"Montana Cans Farben",art_supplies
```

- `date` — `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`;
- `amount` — **плюс приход, минус расход**;
- `category` — можно не заполнять, определится сама (но заполненная точнее).

Счета — `invoices_*.json`:

```json
[
  {"number": "010726", "date": "2026-07-01", "recipient": "FSV",
   "customer_no": "005", "description": "Bemalung Tribünen", "total": 1500.0}
]
```

## Дубликаты — не страшно

Один и тот же платёж, пришедший дважды (перекрывающиеся периоды выписок),
записывается один раз: ключ — дата + сумма + контрагент (+ порядковый номер, если
в один день реально было два одинаковых перевода). Счета дедуплицируются по
номеру и дате. Можно спокойно прислать выписку за квартал, где первый месяц уже
загружен.

## Что происходит после импорта

1. Платежи и счета попадают в `finance.db`.
2. Категории нормализуются (расход не может числиться доходом клиента).
3. Проходит сверка «счёт ↔ оплата» — автоматически только там, где сумма сходится
   копейка в копейку.
4. Спорное попадает в `/todo` — с кандидатами и причиной, на твоё подтверждение.

## Секреты

В эту папку — **только суммы, даты, контрагенты и назначения платежей**.
Не клади сюда PDF с полными реквизитами, доступы в банк, TAN, пароли.
IBAN в выписках лучше затереть до последних четырёх цифр.
