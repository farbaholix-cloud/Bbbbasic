## 1. Железные принципы (уже приняты в кодовой базе — повторять их)

1. **Общая база** `friedman.db` (SQLite) — все боты читают/пишут одну БД.
2. `bot.py` — библиотека: новые sync-функции добавлять в `bot.py`,
   отдельные боты (`jurist_bot.py`, `sales_bot.py`) импортируют его как `B`.
3. **Токены не в git**: паттерн `get_jurist_token()` — env → settings в БД
   (команда `/setsalestoken` по образцу `/setjuristtoken`).
4. **Самолечение**: файлы KB качаются с ветки через `ensure_sales_kb()`
   (`bot.py`, по префиксу `sales_kb/` из `UPDATE_FILES`). Новые файлы KB —
   добавлять в `UPDATE_FILES`.
5. **Один раз в день** — только через `_claim_daily(key)` (`bot.py:~4217`,
   атомарная заявка в БД; переживает два живых процесса).
6. **Claude CLI**: `CLAUDE_BIN = ~/.local/bin/claude`, вызов
   `[CLAUDE_BIN, "-p", prompt, "--allowedTools", "Read,WebSearch,WebFetch", "--model", "sonnet", "--max-turns", N]`,
   таймаут + try/except + fallback — как в `sales_agent_sync()`.
7. **Голос входящий**: `B.transcribe_voice()` (whisper tiny, `bot.py:~330`).
   **Голос исходящий**: `tts.py` → `speak()`/цепочка (ElevenLabs→OpenAI→Edge→Silero).
8. **Часовой пояс**: `B.BERLIN`. Markdown-ответы слать через `B._split_msg(text, 3800)`
   с fallback без разметки (см. `cmd_sales` в `jurist_bot.py`).
9. Каждое изменение: `python3 -m py_compile` на все тронутые файлы; коммиты атомарные.
10. НЕ менять сигнатуры существующих функций. Всё новое — в конец `bot.py`
    или в новые файлы.

## 2. Фаза 1 — MVP: отдельный бот, текст+голос, утренний дайджест ✅ приоритет

### 2.1 `sales_bot.py` (новый файл, по образцу `jurist_bot.py`)
- `get_sales_token()` в `bot.py`: env `SALES_BOT_TOKEN` → settings key
  `sales_bot_token` (со strip() — был баг с пробелом в токене Юриста).
- Владелец-чат: свой ключ `sales_chat_id` в settings (не общий с Юристом).
- Команды:
  - `/start` — легенда возможностей (по образцу RESTART_LEGEND Юриста);
  - `/sales [вопрос]` — разбор воронки/дожатие (уже есть `B.sales_agent_sync`);
  - `/funnel` — воронка цифрами без ИИ: прямой вывод `B.get_funnel_context()`;
  - `/digest` — утренний дайджест вручную (без claim);
  - `/voice_on` / `/voice_off` — отвечать голосом (settings key `sales_voice`).
- Свободный текст → `B.sales_dialog_sync(text)` — НОВАЯ функция в `bot.py`:
  как `sales_agent_sync`, но с памятью диалога: таблица
  `sales_chat(id, role, text, ts)` (по образцу памяти Юриста `remember_lawyer`),
  последние ~30 реплик в промпт.
- Входящее голосовое → скачать OGG → `B.transcribe_voice()` → тот же пайплайн,
  в ответе сначала показать «🎙 Понял: „…“».
- Если `sales_voice=on` — ответ дополнительно озвучить через `tts.py` и отправить
  как voice message; при любой ошибке TTS молча остаётся текст.

### 2.2 Утренний дайджест продаж — 07:00 Europe/Berlin, ежедневно
- `jq.run_daily(sales_morning, time(7, 0, tzinfo=B.BERLIN))` в `sales_bot.py`;
  внутри `_claim_daily("sales_digest:" + today)` — защита от дублей.
- `B.sales_digest_sync()` — НОВАЯ функция в `bot.py`:
  - протокол генерации — читать `sales_kb/references/daily_digest.md` (структура,
    объём **1050–1300 слов ≈ 7 минут чтения**, список книг, тон);
  - **антиповтор**: таблица `sales_digest_log(date, topic, quotes)`;
    в промпт подавать последние 60 тем и ВСЕ использованные цитаты с запретом
    повторять; после генерации — записать новые тему/цитаты;
  - каждый день **WebSearch заново** (свежие статьи/данные о продажах) —
    инструмент уже разрешён в вызове CLI;
  - обязательный блок «применение к FARBAHOLIX сегодня» — с реальными цифрами
    из `get_funnel_context()` (какие сделки в какой стадии, что дожимать).
- **Изображение в чат**: карточка дня — Pillow (PIL): градиентный фон,
  тема дня + главная цитата, подпись FARBAHOLIX · SALES. Шрифт — системный
  с кириллицей (`/System/Library/Fonts/Helvetica.ttc` → fallback DejaVu).
  Отправка: photo с caption-темой, затем текст частями `_split_msg`.
  Ошибка рендера → только текст (как в `morning_focus`, `bot.py:~4098`).
  Pillow добавить в `requirements.txt`, если нет.

## 3. Фаза 2 — доска «Лиды» ✅ РЕАЛИЗОВАНО (июль 2026, dashboard_biz.py)

Реализована НЕ вкладкой в dashboard.py, а отдельным бизнес-пультом
**`dashboard_biz.py` (порт 8770, «FARBAHOLIX · БИЗНЕС»)**: dashboard.py остался
«про жизнь», бизнес вынесен в свой дашборд. Внутри: Воронка (kanban, пишет в
projects — синхронно со вкладкой «Проекты» Секретаря, «оплачено» → finance),
Лиды (таблица leads, правило next_action, «касания сегодня», конвертация в
сделку, отказы с причинами), Деньги (баланс, обороты invoice_archive, порог
§19 25k/100k, топ-клиенты, открытые счета). Замок «обведи точку», rev-протокол,
per-секционная деградация get_data, супервизия из _restart_dashboard,
ссылка — /ip у Секретаря и Продавца. Ниже — исходная спека (для истории):

### 3.1 Данные
Таблица `leads`:
`id, name, channel, city, object_type, area_m2, budget_est, stage,
next_action, next_action_date, touches, notes, project_id, created_at, updated_at`.
Стадии: `new` 📥 Новый → `contacted` 📞 Контакт → `qualified` ✅ Квалифицирован →
`offer` 📄 Оферта → `won` (конвертация: создать проект + ожидаемый профит 🔵 Лид,
записать `project_id`) | `lost` ❌ Отказ (в notes — причина).

### 3.2 Железное правило доски (из activity-based selling, Pipedrive)
**У каждого живого лида всегда заполнено next_action + next_action_date.**
Просроченное действие — красная подсветка. Сортировка в колонке — по дате
следующего касания. Лид без next_action — визуальный дефект (жёлтая рамка).

### 3.3 UI
- `dashboard.py` (мобильный): новая вкладка «Лиды» — 5 колонок, карточка лида:
  имя, канал-эмодзи, бюджет, next_action + дата (красная если прошла), счётчик
  касаний. Тап → меню: сменить стадию / изменить next_action / конвертировать
  в проект / отказ. Версию поднять (на момент написания моб. ≈1.34, Mac ≈1.38 —
  ПРОВЕРИТЬ актуальные в коде и поднять на +0.01).
- `dashboard_mac.py`: зеркально (паттерн зеркалирования уже принят в репо).
- Бот: свободный текст «новый лид: кафе на Berger Str., фасад ~40м², бюджет
  неясен, ответить до пятницы» → Claude-парсинг → INSERT + ответ карточкой.
  `/leads` — сводка: по стадиям + список просроченных касаний.
- Утренний дайджест (2.2) получает блок «касания сегодня: …» из `leads`.

## 4. Фаза 3 — интеграции (e-mail, звонки) — только после Фазы 2

### 4.1 E-mail (human-in-the-loop, НЕ автоотправка)
- IMAP/SMTP Gmail, app-password в settings (`sales_email`, `sales_email_pass`) —
  НЕ в git. Каждые N минут: непрочитанные → фильтр клиентских писем →
  Продавец готовит драфт ответа (на немецком) → в Telegram с кнопками
  **[Отправить] [Править] [Пропустить]** → отправка только после подтверждения.
- Обоснование гибрида: исследование 2026 — объём AI-рассылок ×6, ответы −⅓;
  выигрывает «ИИ готовит, человек утверждает». Плюс UWG §7: холодные
  e-mail без opt-in в Германии запрещены — только ОТВЕТЫ и тёплые контакты.

### 4.2 Звонки («звонковый ассистент», НЕ автообзвон)
- Автоматический обзвон холодных контактов в Германии — юридический риск
  (UWG §7: B2C только с явного согласия, B2B — узкое «предполагаемое согласие»).
  НЕ строить. Вместо этого:
  1) скрипт звонка под конкретного лида (цель, 3 аргумента, ответ на «дорого»,
     следующий шаг) — генерирует Продавец по данным лида;
  2) напоминание в назначенное время (механика remind Секретаря);
  3) после звонка — голосовое боту → Whisper → Продавец фиксирует итог в лида
     и предлагает следующее касание.
