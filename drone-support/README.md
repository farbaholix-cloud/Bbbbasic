# Система учёта эффективности отдела поддержки БпЛА

Рабочий прототип для руководителя отдела поддержки производителя дронов. Консультанты отдела
принимают обращения операторов с линии фронта (Signal, Telegram, WhatsApp, телефон) и фиксируют
каждое обращение в системе. Руководитель видит дашборд отдела с телефона и компьютера.

Интерфейс на украинском языке. Никаких сборщиков и зависимостей: открывается в любом браузере,
работает как приложение на телефоне (можно «Добавить на главный экран»).

## Что внутри

**Консультант**
- «Заступить на дежурство» / «Сдать смену»: время фиксируется автоматически, в конце смены
  самооценка усталости и заметка для следующей смены.
- Форма обращения: канал, приоритет, тип, изделие, время первого ответа (встроенный секундомер
  «Получил → Ответил»), длительность, результат, «техника возвращена в строй», вывод, оценка оператора.
- ОПСЕК-проверка вывода: система не даст сохранить координаты, номера частей, телефоны.
- «Мои показатели»: интегральный балл 0–100, место в отделе, ориентировочная премия.

**Руководитель**
- Обзор: кто сейчас на смене, KPI с динамикой, графики по дням, типам, каналам, приоритетам.
- Команда: таблица всех консультантов с сортировкой, карточка каждого.
- Нагрузка и штат: тепловая карта «когда пишут с фронта», расчёт нужного числа консультантов
  по часам (модель Эрланга C), сколько ставок нужно и где дыры в графике.
- Финансы: ФОП, премии, ЕСВ, накладные, стоимость обращения, условный экономический эффект
  (техника, возвращённая в строй), окупаемость, отчёт по месяцам, распределение премиального фонда.
- Рекомендации: 10 правил анализа данных, каждая рекомендация с цифрами и конкретным действием.
- Предложения к регламенту: принять / на рассмотрение / отклонить с комментарием.
- Отчёт руководству: одна страница для согласования системы, печать в PDF и копирование текста.
- Персонал: добавить сотрудника, ставки, PIN, закрыть доступ при увольнении.
- Настройки: целевые показатели, финансовые параметры, резервная копия, переход с демо на чистую базу.

**Для всех**
- Кнопка «Генеральний регламент» всегда в правом верхнем углу: поиск, оглавление, журнал изменений.
- Внизу каждой страницы — форма «Пропозиція змін до регламенту».

## Демо

Открыть `index.html` (или через любой статический сервер). Система заполнится демо-данными:
8 недель работы отдела из 12 консультантов.

| Кто | PIN |
|---|---|
| Керівник відділу | 0000 |
| Любой консультант | 1111 |

В демо-данные специально заложены ситуации, на которых видна аналитика: нехватка людей на
рассвете, повторяющийся дефект видео у «Крило-2», консультант на грани выгорания, медленный
новичок, сильный кандидат в наставники.

## Как передать реальному пользователю

1. **Пилот на одном устройстве.** В разделе «Налаштування» нажать «Почати з чистої бази»,
   сменить PIN руководителя, завести сотрудников. Данные хранятся в браузере — делайте резервные копии (JSON).
2. **Вся команда, общая база.** Нужен сервер с Node.js 18+:
   ```bash
   DSS_USER=support DSS_PASS=длинный-пароль PORT=8080 node backend/server.js
   ```
   и в `assets/config.js`: `storage: 'rest'`, `seedDemo: false`. Сервер раздаёт интерфейс
   и хранит базу в `backend/data/db.json`. Обязательно за HTTPS (nginx, Caddy, Cloudflare Tunnel).
   Существующие данные переносятся через «Резервна копія» → «Відновити з копії».
3. **Промышленная версия.** `backend/schema.sql` — схема PostgreSQL/Supabase с теми же полями.
   Нужно заменить PIN на нормальную авторизацию (SSO компании или Supabase Auth) и включить
   правила доступа (консультант видит только своё). Интерфейс менять не нужно: достаточно
   переписать `RestAdapter` в `assets/store.js`.

Название компании и отдела — в `assets/config.js`. Справочники (каналы, типы, изделия) —
в `assets/dict.js`.

## Генеральный регламент

Текст — в `assets/reglament.js` (единственный источник; из интерфейса можно скачать `.md`).
13 разделов: общие положения, роли, режим дежурств, каналы связи, стандарты реагирования
(критичное — ответ до 30 с), классификация, учёт в системе, **ОПСЕК**, эскалация в производство,
психологическая безопасность и ротация, оценка эффективности и премии, обучение, порядок изменения
регламента. Новая редакция: изменить текст, поднять `version`/`date`, добавить строку в `changelog`.

## Структура

```
drone-support/
  index.html            точка входа
  assets/config.js      настройки развёртывания (единственный файл для переноса)
  assets/reglament.js   генеральный регламент
  assets/dict.js        справочники формы
  assets/store.js       слой данных: браузер или сервер
  assets/analytics.js   KPI, балл, Эрланг C, финансы, рекомендации
  assets/charts.js      графики на SVG без библиотек (работают офлайн)
  assets/seed.js        генератор демо-данных
  assets/app.js         интерфейс
  assets/app.css        оформление, светлая и тёмная тема
  backend/server.js     сервер без зависимостей для общей базы
  backend/schema.sql    схема для PostgreSQL / Supabase
```

## Ограничения прототипа

- PIN-коды хранятся открыто — это прототип. Для реальной работы: пункт 3 выше.
- В режиме `local` у каждого устройства своя база; для команды нужен сервер (пункт 2).
- Экономический эффект — консервативная оценка: число единиц техники, возвращённых в строй,
  умноженное на среднюю стоимость изделия (меняется в настройках).
