# Backstage — платформа агентства Backstage AI Agency

Панель для клиентов агентства: дашборд на компьютере и телефоне плюс чат с командой из восьми ИИ-агентов (Backstage Crew). Работает по IP-адресу арендованного сервера, без домена. Выросла из системы Фридмана (`friedman_bot/`), но рассчитана на любого клиента, а не только на Farbaholix.

| Что | Где |
|---|---|
| Вход клиента | `http://<IP>:8800/` или персональная ссылка `http://<IP>:8800/c/<код>?k=<ключ>` |
| Дашборд и чат | `/app` |
| Инструкция для клиента | `/guide` (её же отправляй новым клиентам) |
| Админка владельца | `/admin` |

## Что взято из опыта Фридмана

- **Один собеседник вместо восьми чатов.** Ходить к юристу, маркетологу и финансисту по отдельности оказалось неудобно. Здесь клиент пишет Майе (продюсерке), а она сама зовёт специалистов (инструмент `ask_specialist`) и сводит ответ. Прямой чат со специалистом остался, но он вторичен.
- **Дашборд как общая память.** Агенты видят весь дашборд клиента перед каждым ответом и сами его меняют: карточки, дедлайны, KPI, графики. Клиент правит его руками.
- **Базы знаний → справочники.** Справочники `*_kb` Фридмана написаны под одного человека (имена, суммы, статус). Чтобы дать их другим клиентам, обезличенные версии кладутся в `packs/` (см. ниже).
- **База опыта.** Новое: агенты сохраняют выводы (`save_insight`). Владелец просматривает их в админке и одобренные обезличенные записи переносит в общий плейбук, который видят агенты всех клиентов. Так из многолетней работы с Farbaholix и другими клиентами вырастает база агентства.

Telegram-боты Фридмана остаются твоими личными: они завязаны на твои финансы, счета и базы, поэтому их код клиентам не раздаётся. Вместо этого у каждого клиента может быть **свой бот**: он создаёт его в @BotFather, вставляет токен в настройках панели, и бот пишет той же команде (`telegram_bridge.py`). Инструкция для клиента — в `/guide#telegram`.

## Устройство

```
backstage/
  server.py           HTTP-сервер: страницы, API клиента, API админки, фоновые задачи
  brain.py            вызовы Claude API: агенты, инструменты дашборда, веб-поиск, расход в $
  store.py            SQLite: клиенты, виджеты, переписка, расход, база опыта, сессии
  telegram_bridge.py  боты клиентов (long polling, по потоку на бота)
  manage.py           консольные команды: создать клиента, выдать ключ, лимит
  agents/             промпты команды: _common.md + по файлу на агента, agents.json — состав
  packs/              справочники для агентов (_all/ — всем, <agent>/ — одному)
  static/             login, app (дашборд+чат), guide, admin
  deploy/             systemd-юниты и update.sh
```

Стек как у дашборда Фридмана: стандартная библиотека Python (`ThreadingHTTPServer`) + SQLite, плюс официальный SDK `anthropic`. Фреймворков нет, сборки фронтенда нет.

## Модели и токены

- **Обычный чат** — `claude-opus-5-5` (effort `high`).
- **Глубокий анализ и Проверка потенциала** — `claude-fable-5-1` (effort `xhigh`), самая мощная из общедоступных моделей Claude, с веб-поиском.
- Модели и effort меняются в `.env`, а для отдельного клиента — в админке.
- Включён серверный фолбэк (`fallbacks: "default"`): если модель отклонит запрос, API сам повторит его на запасной модели.

**Важно про оплату.** Боты Фридмана работают через `claude` CLI по твоей личной подписке. Для сервиса, которым пользуются клиенты, нужен **ключ Claude API**: console.anthropic.com → API Keys, баланс пополняется в Billing. «Купить больше токенов» значит пополнить этот баланс. Каждый вызов считается по цене модели и записывается в `usage` по клиенту: расход видно в админке, у клиента в шапке и в KPI «Бюджет ИИ».

Ориентир по стоимости (зависит от длины переписки и дашборда):

| Действие | Примерно |
|---|---|
| Сообщение в чат (Opus 5.5) | $0.05–0.15 |
| Сообщение, где Майя зовёт 2–3 специалистов | $0.20–0.60 |
| Глубокий анализ / Проверка потенциала (Fable 5.1 + поиск) | $1–5 |

Цены за 1M токенов: Fable 5.1 — $10 вход / $50 выход, Opus 5.5 — $4 / $20; веб-поиск — $10 за 1000 запросов. Системные промпты кэшируются, повторное чтение стоит в 20–40 раз дешевле. У каждого клиента есть месячный лимит: при исчерпании команда замолкает до нового месяца или пока ты не поднимешь лимит.

## Установка на сервер

Пример для Ubuntu/Debian. Код живёт в `/opt/backstage`, сервисы работают от отдельного пользователя `backstage`.

```bash
# 1. Пользователь и код
sudo adduser --system --group --home /opt/backstage backstage
sudo -u backstage git clone https://github.com/farbaholix-cloud/bbbbasic.git /opt/backstage
#   если репозиторий приватный — понадобится deploy key или токен GitHub
cd /opt/backstage
sudo -u backstage python3 -m venv venv
sudo -u backstage venv/bin/pip install -r backstage/requirements.txt

# 2. Настройки
sudo -u backstage cp backstage/.env.example backstage/.env
sudo -u backstage nano backstage/.env      # ANTHROPIC_API_KEY, BACKSTAGE_ADMIN_KEY
sudo chmod 600 backstage/.env

# 3. Сервисы
sudo cp backstage/deploy/backstage.service backstage/deploy/backstage-telegram.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now backstage backstage-telegram

# 4. Порт наружу (если включён ufw)
sudo ufw allow 8800/tcp

# 5. Первый клиент
cd /opt/backstage/backstage
sudo -u backstage BACKSTAGE_PUBLIC_URL=http://<IP>:8800 ../venv/bin/python manage.py add farbaholix "Farbaholix" 50
```

Последняя команда печатает персональную ссылку клиента. Дальше клиентов удобнее заводить в `/admin`.

Обновление после изменений в git: `sudo /opt/backstage/backstage/deploy/update.sh`. Логи: `journalctl -u backstage -f` и `journalctl -u backstage-telegram -f`.

Если на этом же сервере живут боты Фридмана, конфликтов нет: Backstage использует порт 8800 и свою базу `backstage/backstage.db`, а порты 8765/8766 и `friedman.db` не трогает.

## HTTPS без домена

Без сертификата браузер пишет «Не защищено», а ключи и переписка идут открытым текстом. Минимум — самоподписанный сертификат на IP:

```bash
sudo -u backstage mkdir -p /opt/backstage/backstage/tls && cd /opt/backstage/backstage/tls
sudo -u backstage openssl req -x509 -newkey rsa:2048 -nodes -days 825 \
  -keyout key.pem -out cert.pem -subj "/CN=<IP>" -addext "subjectAltName=IP:<IP>"
```

В `.env` раскомментируй `BACKSTAGE_TLS_CERT` / `BACKSTAGE_TLS_KEY`, перезапусти сервис и давай клиентам ссылки на `https://<IP>:8800`. При первом входе браузер один раз попросит подтвердить сертификат. Когда появится домен, лучше поставить перед сервером Caddy или nginx с Let's Encrypt, а Backstage оставить на `127.0.0.1`.

## Справочники агентов (packs)

Файлы `packs/_all/*.md` добавляются в промпт всех агентов, `packs/<agent>/*.md` — одного (`konrad`, `ben`, `noa`…). Например, справочник немецкого права для художников из `friedman_bot/legal_kb/references/` можно положить в `packs/konrad/`, **предварительно убрав** личные данные (имена, суммы, твой статус и решения Finanzamt). Справочники кэшируются, поэтому большие файлы почти не увеличивают цену повторных сообщений.

## Резервные копии

База одна: `backstage/backstage.db` (+ файлы `-wal`/`-shm`). Безопасная копия на ходу:

```bash
sqlite3 /opt/backstage/backstage/backstage.db ".backup '/opt/backstage/backup/backstage-$(date +%F).db'"
```

Удобно повесить это в cron рядом с бэкапами Фридмана.

## Безопасность

- В базе лежит только хэш ключа клиента. Ссылка с ключом показывается один раз; «Новый ключ» в админке сразу выкидывает все старые входы.
- Подбор ключей тормозится: 10 неудачных попыток с одного IP — пауза 10 минут.
- Telegram-бот клиента отвечает только чату, который первым написал ему `/start`.
- Месячный лимит расхода на каждого клиента; один ответ за раз на клиента, чтобы двойной клик не тратил бюджет дважды.
- Сессии хранятся 30 дней, cookie `HttpOnly` + `SameSite=Lax` (`Secure` при HTTPS).
